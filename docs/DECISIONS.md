# Decision log

Trade-offs and deviations from the build brief, newest last. Each entry: date, decision, reason.

| Date | Decision | Reason |
|---|---|---|
| 2026-10-20 | TypeScript is pinned to `~6.0`, not the newer 7.x line. | `typescript-eslint` 8.x supports TypeScript `<6.1`. Strict type-aware linting matters more than the newest compiler. |
| 2026-10-20 | Python 3.12 is supplied by `uv` (`requires-python = ">=3.12,<3.13"`). | The brief fixes Python 3.12; the dev machine's default is 3.14. uv pins the interpreter per project, so nothing depends on the system Python. |
| 2026-10-20 | npm, not pnpm, for the web app. | There is one JavaScript package. npm ships with every Node image, which keeps Dockerfiles and CI simple. |
| 2026-10-20 | Backend unit tests run on in-memory SQLite + fakeredis; PostgreSQL is exercised by the Compose smoke test and E2E runs. | Tests stay fast and runnable offline. Models use portable SQLAlchemy types with PostgreSQL variants (`JSONB`, `ARRAY`) where the brief asks for them. |
| 2026-10-20 | Uvicorn runs `create_app` in `--factory` mode. | No connections or settings are read at import time, which keeps tests and Alembic free of side effects. |
| 2026-10-20 | The browser reaches the API only through nginx on the same origin. | Auth cookies stay first-party (`SameSite=Strict` works), and the CSP can use `connect-src 'self'`. |
| 2026-10-20 | Redis runs with persistence disabled. | Redis holds only rate-limit counters and short-lived session data. Nothing in it needs to survive a restart, and nothing sensitive should land on disk. |
| 2026-10-20 | API docs (`/api/docs`, OpenAPI JSON) are disabled when `APP_ENV=production`. | Reduces attack surface; docs remain available in development. |
| 2026-10-20 | No `deleted_at` column on `users`. | Account deletion is a hard delete (brief, feature 11), so a soft-delete timestamp would never be set. The audit log keeps an anonymised record that a deletion happened. |
| 2026-10-20 | Added a `refresh_tokens` table (not in the brief's data model). | Rotating refresh tokens need durable server-side state for revocation and reuse detection. Redis runs without persistence, and losing tokens on restart would permanently lock anonymous users out of their data. Tokens are stored as SHA-256 digests. |
| 2026-10-20 | Consents are one row per user and scope (current state); history lives in `audit_log` as `consent.grant.*` / `consent.revoke.*`. | Fast "is this granted?" checks, with a complete change history for DPDP accountability. Scopes left off at sign-up are stored as a choice, not logged as revocations. |
| 2026-10-20 | Age confirmation and `core` consent are required in the same request that creates a session (`POST /auth/anonymous`, `/auth/register`). | No account can exist without a recorded 18+ confirmation and core consent. |
| 2026-10-20 | CSRF defence is `SameSite=Strict` httpOnly cookies, JSON-only request bodies and a single same-origin deployment; no separate CSRF token. | Browsers never attach Strict cookies to cross-site requests, and the API is never served cross-origin in production. Re-evaluate before allowing any cross-origin client. |
| 2026-10-20 | Auth rate limit defaults to 30 requests per minute per IP, applied to credential and session-creation endpoints only. | College campuses put many students behind one NAT address; 10 per minute would block legitimate sign-ups during a class session. `/auth/me` is not throttled. The limiter fails open if Redis is down. |
| 2026-10-20 | Tamil UI copy is a first draft written in-house and needs review by a native speaker before release. | The brief requires Tamil from day one. Questionnaire items are a separate matter (see Phase 2) and are never machine- or self-translated. |
| 2026-10-20 | Fonts are self-hosted (`@fontsource-variable/*`: Bricolage Grotesque, Plus Jakarta Sans, Noto Sans Tamil). | Works offline, needs no third-party requests (privacy, CSP `font-src 'self'`), and Noto Sans Tamil renders Tamil script in every heading and paragraph. |
| 2026-10-20 | The landing page uses a live box-breathing guide as its hero visual instead of photography. | It is a real product feature, works offline, and avoids stock imagery of distressed people. It has a pause control (WCAG 2.2.2) and stays static under reduced motion. |
| 2026-10-20 | E2E tests run with `prefers-reduced-motion: reduce`. | Entrance fades made axe-core measure contrast mid-animation. Reduced motion renders the final state, which is what users read. |
| 2026-10-20 | PHQ-9 and GAD-7 items are shown in English, with the Tamil UI around them and a notice saying so. | The brief forbids machine or in-house translation of questionnaire items. Official Tamil translations are distributed through the PHQ Screeners programme (phqscreeners.com, "no permission required to reproduce, translate, display or distribute"), but this build could not obtain and verify that text. To add it: copy the official PDF wording verbatim into `apps/api/app/assessments/instruments.py`, set `translation_available` for `ta`, and record the source and download date here. |
| 2026-10-20 | Item wording keeps the official punctuation, including em dashes in PHQ-9 items 6 and 8. | Validated instruments are reproduced verbatim. The no-em-dash rule applies to our own copy, not to licensed instrument text. |
| 2026-10-20 | The UI calls the instruments "Mood check (PHQ-9)" and "Worry check (GAD-7)", and the section "Self-checks". | The official titles contain "Patient" and "Disorder", which the microcopy rules avoid. "Check-in" is kept for the daily mood log (Phase 6), so the two never collide. |
| 2026-10-20 | Added a nullable `functional_difficulty` column to `assessments`, collected for both instruments and never scored. | The brief asks for the PHQ-9 functional-difficulty question; the official GAD-7 form carries the same question, and asking it on both keeps the flow consistent. |
| 2026-10-20 | Any PHQ-9 item 9 answer above 0 is logged as a `safety_event` with `level=urgent` and `detector=questionnaire`, and forces the next step to "speak with a professional". | High recall over precision, and the brief says item 9 triggers the safety flow "regardless of total score". `questionnaire` extends the detector enum so the event's origin stays truthful. |
| 2026-10-20 | The crisis card opens the moment item 9 is answered above 0, before the remaining question and before any result. A second safeguard opens it after submission if the first was missed. | "Immediately, before the result screen" in the brief. |
| 2026-10-20 | The web app bundles an offline copy of the crisis resources, generated from `resources.yaml` by `python -m app.safety.export_fallback`; a backend test fails if they drift. | The crisis card must work with no network and must never wait on a request. One reviewed source of truth, two delivery paths. |
| 2026-10-20 | Tele-MANAS details were verified on 2026-10-20 against secondary sources (Vikaspedia, IIT Kanpur counselling page) because telemanas.mohfw.gov.in failed TLS certificate verification; 112 was verified against press coverage of the ERSS launch. | `last_verified` must be honest. Re-check against the official site at the next review. |
| 2026-10-20 | "Need help now?" uses the calm accent colour; red appears only inside the crisis card. | Brief: no alarm red outside the crisis card. |
| 2026-10-20 | Safety layer 2 is a frozen multilingual sentence encoder (`intfloat/multilingual-e5-small`, MIT) with a small logistic head, not a classifier trained from scratch. | With about 250 training examples, an n-gram model cannot generalise: blind-holdout urgent recall was 0.47. The pretrained encoder raised it to 0.91. It runs on CPU in about 15 ms and is baked into the Docker image, so the app still works offline. |
| 2026-10-20 | PyTorch (CPU build) and transformers are API dependencies from Phase 3, not Phase 5. | The safety engine needs the encoder. The CPU-only wheel index keeps the image smaller than the default CUDA build. |
| 2026-10-20 | Classifier thresholds are picked by cross-validation with a false-positive cap (10% urgent, 15% any flag), not by recall alone. | A recall-only rule chose a threshold that marked 80% of all messages urgent: a "pass" on paper that would replace almost every conversation with a crisis card. |
| 2026-10-20 | Each blind holdout is scored once, after the engine is frozen, and is reported as it came out, including when it misses the gate (holdout C: 0.912). Holdouts that informed a later change are relabelled as development sets. | Tuning on the red-team set made it an optimistic measure (0.988 on it, 0.447 on the first blind set). The blind numbers are the honest estimate of generalisation. |
| 2026-10-20 | Third-party subjects downgrade even plan and means rules ("someone in our hostel talked about jumping off the terrace"), while jokes, quotes and research context never do. | Someone else's plan calls for the elevated flow (support for helping a friend), not the person's own crisis card. A joke wrapped around a real plan must stay urgent. |
| 2026-10-20 | The safety engine falls back to the hashed classifier (and logs a warning) if the encoder cannot load; it never raises. | A missing model must not take the safety check down with it. |
| 2026-10-20 | The assistant reply is fully generated and run through the output filter before any of it streams to the browser. | A partially streamed unsafe reply cannot be taken back. Streaming the filtered reply word by word keeps the UI responsive at the cost of time-to-first-token. |
| 2026-10-20 | Without `chat_history` consent the server stores no chat content; the browser sends the last turns with each request instead. | "Session-only" history still needs context. Keeping it in the tab means nothing persists server-side. |
| 2026-10-20 | When `LLM_PROVIDER=anthropic` but the user has not granted `cloud_llm`, the mock provider answers instead of a cloud call. | Cloud processing requires explicit consent. Self-hosters should set `LLM_PROVIDER=ollama` for real local replies. |
| 2026-10-20 | `GET /privacy/export` returns one JSON file instead of a zip. | Same data, simpler to inspect and to test; a zip adds no protection. |
| 2026-10-20 | Chat mood adaptation uses the latest check-in mood only; the text emotion model (Phase 5) is not built yet. | No unevaluated model is used to steer replies. |
| 2026-10-21 | Text emotion uses `SamLowe/roberta-base-go_emotions` (MIT), not `j-hartmann/emotion-english-distilroberta-base`. | The DistilRoBERTa model declares no licence on its model card, so it cannot be verified for use. The chosen model is trained on GoEmotions train, so the GoEmotions test split is a fair held-out evaluation. |
| 2026-10-21 | Emotion "Is this right?" answers are not stored. | Collecting feedback means a new data use; it needs its own consent scope and an evaluation plan first. |
| 2026-10-21 | Tanglish is detected with a script check plus a small list of romanised-Tamil function words (two or more matches). | Simple, explainable and enough to return `unsupported`. A trained language-ID model is a Track C item. |
| 2026-10-21 | Safety and emotion inference run in the threadpool, not on the event loop. | Synchronous model calls blocked every other request; under parallel E2E load sign-ups timed out. |
| 2026-10-21 | Mood patterns use Pearson correlation over days with both values, hidden below 14 days, described in words (weak / moderate / strong) and always labelled "patterns, not causes". | The brief's rule; plain words avoid false precision. |
